# AI 海外客服差评升级预警员

英文名：AI Overseas Support Escalation Alert Analyst

一句话：每天替老板读已授权、已脱敏的客服工单、邮件、公开评论和退款理由，把可能变成差评、拒付、平台投诉的客户问题提前标红。

## 适合谁

- 独立站、Amazon、TikTok Shop、Shopify、DTC 品牌，有海外客服和售后团队。
- 客服工单、邮件、平台评论、退款理由分散在多个系统里，主管每天只能抽样看。
- 老板最怕差评、拒付、平台纠纷和售后补发成本失控。

## 老板痛点

客户通常会先发出信号：催三次没人回、包裹破损、退款迟迟不到、安装失败、配件缺失、威胁差评或平台投诉。团队如果只看“今日回复量”，很容易漏掉这些快要升级的问题。等公开差评出现，客服、仓库、物流、质检才开始互相追问，成本已经上桌。

## 岗位描述

这个数字员工每天接收授权客服工单、邮件摘要、公开评论、退款理由、物流状态摘要、产品说明和团队售后规则。它不直接回复客户，只做五件事：找升级信号，判断可能后果，分派负责人，生成可审核处理建议，沉淀重复问题。

## 可接手任务

1. 找出“没人回复、反复催、威胁差评、要拒付、要投诉平台、收到破损货、退款超时”等风险信号。
2. 按差评、退款、拒付、平台纠纷、物流延误、质量问题、配件缺失、安装失败等主题分类。
3. 标出订单阶段、产品、渠道、已等待时长、建议负责人。
4. 生成客服主管可审的处理建议：先确认什么，找谁处理，哪些话不能说。
5. 每天输出老板看的一页升级预警：高风险数量、Top 问题、责任人、今天必须处理的样本。
6. 把重复升级原因沉淀成 FAQ、售后流程和产品资料补洞清单。
7. 记录人工处理结果，下一天检查同类问题有没有再出现。

## 能力模块

| 模块 | 工具 / Skill | 作用 | 风险边界 |
|---|---|---|---|
| 工单与评论读取 | Chatwoot / Zammad / Maxun | 汇总授权工单、公开评论、退款理由和截图证据 | 不抓未授权私聊，不保存敏感个人信息 |
| 风险信号识别 | Dify / ChatGPT / Claude 工作流 | 判断差评、退款、拒付、投诉苗头 | 只给风险分，不替客服下结论 |
| 流程分派 | n8n | 高风险样本推给客服主管、仓库、物流、质检 | 不自动向客户发送消息 |
| 台账与复盘 | NocoDB / Baserow | 维护问题、责任人、状态、处理结果 | 订单号、邮箱、电话需脱敏或权限控制 |
| 规则知识库 | Outline / BookStack | 存售后话术边界、退款规则、不可承诺清单 | 赔偿、平台申诉、法律责任须人审 |

## 工作机理

```text
授权客服工单 + 邮件摘要 + 公开评论 + 退款理由 + 物流状态 + 售后规则
        ↓
去隐私 → 找升级信号 → 判断可能后果 → 分派负责人 → 生成处理建议
        ↓
高风险清单 + 老板日报 + 客服主管人审表 + FAQ / SOP 补洞建议
        ↓
客服主管看回复边界，仓库/物流/质检看事实，老板看高风险样本和重复问题
```

## 真实任务示例 / 提示词

### 1. 客服升级风险标注

> 你是跨境电商客服主管的升级预警助手。下面是已脱敏的客服工单 / 评论 / 退款理由摘要。请不要替客服回复客户，只判断哪些样本可能升级为差评、拒付、平台投诉或公开争议。输出表格：样本编号、风险等级、升级信号、可能后果、建议负责人、客服回复前必须确认的信息。遇到退款、赔偿、补发、法律责任、平台申诉，一律标为“人工主管确认”。

### 2. 老板一页预警日报

> 请把今天的客服升级风险表压缩成老板能看懂的一页日报。只保留：高风险样本数量、最容易引发差评的 5 个问题、涉及产品 / 渠道、今天必须处理的人、不能由 AI 决定的事项。不要写行业分析，不要承诺能避免差评。

### 3. 客服处理建议草稿

> 下面是一条高风险客服样本和我们已确认的订单事实。请生成给客服主管看的处理建议，不要直接写给客户。输出：先查什么、找谁确认、可用回复方向、不能承诺的话、升级给谁。不得承诺退款、补发、赔偿、到货日期或平台处理结果。

### 4. 重复问题复盘

> 请阅读这批已人工处理过的高风险客服样本，找出重复升级原因。输出：问题类型、出现次数、客户原话关键词、现有流程缺口、建议补到 FAQ / 售后 SOP / 产品页的位置、需要负责人确认的字段。不要引用客户姓名、邮箱、电话和订单号。

## 人类主管验收

- 客服主管每天抽查 20 条：风险等级是否误判，处理建议有没有越权承诺。
- 老板只看高风险样本、涉及产品 / 渠道、今天该谁处理、重复问题是否减少。
- 仓库、物流、质检、售后负责人确认事实：是否破损、是否漏件、是否延误、是否可补发。
- 所有退款、赔偿、平台申诉、法律责任、公开回应，必须人工确认。
- 每周复盘：提前处理了几条高风险样本，哪类问题最常重复，FAQ / SOP / 产品页补了哪些内容。

## 不能自动化的事

- 不自动回复客户，不承诺退款、补发、赔偿、折扣、到货日期、平台申诉结果。
- 不处理未授权聊天记录、个人隐私、合同、报价、付款资料和平台账号凭据。
- 不替客服主管判断是否退款、是否补发、是否承担责任。
- 不绕过平台规则抓取私密数据，不删除评论，不规避审核。
- 不把模型判断当最终事实；高风险样本必须人工复核。

## 第一周试点

- Day 1：选最近 7 天 100–200 条已授权且脱敏的工单、邮件摘要、退款理由和公开评论。
- Day 2：定义 10 个升级信号：催促、威胁差评、拒付、平台投诉、退款超时、破损、物流卡住、配件缺失、安装失败、客服未回复。
- Day 3：让 AI 做第一轮风险标注，输出高 / 中 / 低风险和理由。
- Day 4：客服主管抽查 20 条高风险和 20 条低风险，修正规则。
- Day 5：接入 n8n，把高风险样本推给负责人，不自动回复客户。
- Day 6：整理 Top 10 重复升级原因，补 FAQ、售后流程或产品说明。
- Day 7：老板看复盘：提前拦下几条差评风险、处理超时原因、下周要改哪 3 个流程。

## 相关 Skill 工具栈

1. **Chatwoot**：开源客服系统，适合汇总独立站聊天、邮件和社媒消息；权限要分级，客户资料需脱敏。
2. **Zammad**：开源工单系统，适合按状态、责任人和等待时长管理售后问题；不自动对外承诺。
3. **Dify / Claude / ChatGPT 工作流**：做风险信号分类和处理建议草稿；模型输出必须客服主管审核。
4. **n8n**：把高风险样本推给客服主管、仓库、物流、质检；只推内部提醒，不自动发客户消息。
5. **NocoDB / Baserow + Outline**：沉淀升级台账、话术边界、FAQ 和 SOP；不要存放未脱敏客户隐私。
