# AI 海外节日营销日历员

> 每天认识一个出海 AI 员工：它不替老板决定折扣，只把海外节日、平台大促、SKU、素材和负责人提前排成一张能执行的日历。

## 适合谁
- DTC / 独立站老板：节日营销靠临时催，邮件、广告图、页面和库存经常抢时间。
- Amazon、TikTok Shop、Walmart、eBay 团队：平台促销报名、素材截止和库存检查容易漏。
- 外贸品牌与工厂：要把目标国家节日、行业节点、展会节奏和渠道活动合在一张表里。

## 老板痛点
很多团队做活动时，问题不在创意少，而在准备动作散。节日前一周，运营问主推 SKU，设计还在等 brief，广告手不知道预算，客服不知道话术，老板才发现库存不敢推。最后活动看起来上线了，实际每一步都在临时补。

## 这个岗位每天做什么
输入：目标国家、平台/渠道、主推 SKU、库存和毛利区间、品牌活动计划、公开节日/平台大促资料、上一轮复盘。

输出：
- 未来 30/60/90 天活动日历；
- 每个节点适配的 SKU、国家、渠道和准备天数；
- Listing/落地页、邮件、广告素材、达人内容、库存和客服话术清单；
- 负责人和截止日期提醒；
- 老板需要确认的折扣、预算、库存和平台规则风险。

## 可接手任务
1. 汇总目标市场节日、平台大促、行业节点和品牌自有活动。
2. 给每个节点标记适合的 SKU、国家、渠道和提前准备天数。
3. 把一个活动拆成 Listing/落地页、邮件、广告素材、达人内容、库存、客服话术。
4. 每天提醒快到期动作：缺图、缺页面、缺折扣确认、缺库存判断。
5. 写活动 brief 草稿，包含主题、主推品、页面改动、邮件角度、社媒话题。
6. 对上一轮活动做复盘：哪些任务晚了，哪些 SKU 不适合再推，哪些素材能复用。
7. 给老板输出一页 30 天雷达：本周确认什么，下周交付什么，哪些风险卡住。

## 能力模块
| 模块 | 做什么 | 工具栈 |
|---|---|---|
| 节点采集 | 抓公开节日、平台大促、行业营销日历 | RSSHub / n8n / python-holidays |
| 热度观察 | 看目标市场搜索兴趣和主题变化 | pytrends / Google Trends |
| SKU 匹配 | 按国家、品类、库存、毛利、历史表现标记适合度 | 表格 / LLM / Metabase |
| 任务拆解 | 把活动拆成页面、邮件、广告、达人、客服、库存动作 | ChatGPT / Claude / Gemini |
| 提醒与复盘 | 提醒负责人，记录延期和风险 | n8n / 飞书 / Metabase |

## 工作机理
国家 / 平台 / SKU → 公开节日与平台节点 → 判断 SKU 适配 → 拆准备动作与截止日期 → 每天提醒负责人 → 老板确认折扣、预算、库存和规则 → 活动后复盘下一轮。

## 可复制任务提示词

### 1. 生成 60 天活动日历
请扮演跨境电商的海外节日营销日历员。我的目标市场是【国家/地区】，渠道是【独立站/Amazon/TikTok Shop/邮件/社媒】，主推品类是【品类】。请整理未来 60 天值得关注的节日、平台促销、行业节点，并输出：节点名称、目标人群、适合的 SKU 类型、建议提前准备天数、需要老板确认的事项。不要编造平台报名资格；不确定的规则请标“需人工查证”。

### 2. 拆活动准备清单
下面是一个活动想法：【活动主题】。请把它拆成跨境团队 21 天准备清单，包含 Listing/落地页、邮件、广告素材、达人内容、库存、客服话术、折扣确认。每项写清负责人角色、截止日期、交付物和老板需要看的风险点。

### 3. 检查本周活动风险
请根据下面的活动日历和任务进度，找出本周最容易延期或出错的 5 件事。优先检查：主图/视频未完成、折扣未确认、库存不足、页面没更新、达人寄样来不及、平台规则没查证。输出给老板看的简短清单：问题、影响、今天该找谁。

### 4. 活动后复盘
这是上一轮促销的活动计划、实际交付时间和销售/邮件/广告数据。请总结：哪些准备动作晚了，哪些 SKU 不适合继续推，哪些素材可复用，下一轮提前 14 天必须确认什么。不要给“保证增长”的结论，只给可人工复核的改进建议。

## 人类主管验收
- 每天看：未来 30 天活动节点、7 天内到期任务、缺负责人/缺素材/缺折扣确认的项目。
- 每天抽查：节日和平台节点是否来自公开页面，SKU 匹配理由是否合理，AI 是否编造了报名规则。
- 每周看：准备动作延期次数、活动前 7 天仍未完成项、活动后复盘中反复出现的卡点。

## 不能自动化的事
- 不能自动决定折扣、预算、库存分配、促销报名或达人合作报价。
- 不能替代平台规则、广告政策、税务/合规和知识产权审核。
- 不能承诺销量、转化率、ROI 或排名结果。
- 不能把客户隐私、内部价格、合同、未公开新品计划放进公开内容。

## 第一周试点
1. 选 3 个目标国家、20 个主推 SKU、2 个渠道，整理现有活动计划。
2. 拉出未来 60 天公开节点，标出高/中/低优先级。
3. 为前 5 个节点匹配 SKU，写出页面、邮件、广告、达人、库存动作。
4. 设置 21/14/7/3 天提醒，把负责人写进表格或项目管理工具。
5. 老板只确认三件事：主推 SKU、折扣/预算上限、哪些节点不做。
6. 跑一次风险检查，删除空泛活动，保留两周内能交付的任务。

## 相关 Skill 工具栈
- [n8n](https://github.com/n8n-io/n8n)：定时抓取公开节点、发送负责人提醒。风险：平台账号和内部数据要分权限。
- [RSSHub](https://github.com/DIYgod/RSSHub)：订阅平台帮助中心、品牌博客、行业营销日历更新。风险：只订阅公开来源。
- [pytrends](https://github.com/GeneralMills/pytrends)：观察目标市场搜索兴趣变化。风险：趋势信号不能直接等同销量预测。
- [python-holidays](https://github.com/dr-prodigy/python-holidays)：补充各国节假日基础日历。风险：地方节日和平台活动仍需人工确认。
- [Metabase](https://github.com/metabase/metabase)：复盘活动准备延期和结果数据。风险：内部销售/毛利数据不得公开。

## 安全边界
可公开讲岗位和流程；不可公开客户名单、真实订单、内部价格、合同、返点、报价、未公开新品或渠道预算。该岗位只做公开节点收集、准备动作拆解、提醒和复盘，不替代老板、运营负责人、平台规则审核、法务/合规或财务判断。
