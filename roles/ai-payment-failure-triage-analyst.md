# AI 海外支付失败归因员 / AI Payment Failure Triage Analyst

> 每天把“客户付不了钱”的原因拆出来，告诉老板先查哪个国家、哪种支付方式、哪段结账流程。

## 适合谁

- Shopify、WooCommerce、独立站、B2B 小额在线收款团队。
- 广告和内容带来了访问量，但付款页经常掉单的公司。
- 老板、运营、财务、客服总在追问“客户到底为什么没付成”的团队。

## 老板痛点

付款失败看起来像客户没兴趣，实际可能是收款链路在漏钱。客户到了 checkout，银行卡被拒、3DS 验证卡住、本地支付方式没出现、币种和税费让他犹豫。老板看到的是转化差，运营看到的是订单没进来，财务看到的是收款少了。中间那一段没人每天拆开看。

## 岗位描述

这个数字员工每天接收脱敏支付失败事件、站点漏斗数据和客服反馈，把失败按国家、设备、支付方式、错误码聚合，输出一页“支付失败归因早报”：昨天哪里失败最多、可能是什么原因、该交给运营/财务/技术/客服谁去确认。

## 可接手任务

1. 按国家、币种、支付方式、错误码统计失败次数。
2. 对比商品页、购物车、结账页、支付失败、付款成功五段数据。
3. 标出异常集中点：某个国家、设备或支付方式突然变差。
4. 把 Stripe / WooCommerce 错误码翻译成运营能读懂的话。
5. 把客服里“付不了”的反馈合并到同一张原因表。
6. 给老板生成一页日报：影响范围、优先排查项、负责人。
7. 跟踪修复后 3 天支付成功率是否变好。

## 能力模块

| 模块 | 做什么 | 人工确认点 |
|---|---|---|
| 支付失败读码 | 读取失败状态和错误码，只做原因分类 | 不碰银行卡号，不替银行下结论 |
| 结账漏斗看板 | 看客户卡在购物车、结账页还是付款页 | 只看聚合数据和脱敏事件 |
| 异常聚合提醒 | 每天固定时间整理国家、设备、支付方式异常 | 高风险项交给人确认 |
| 客服反馈匹配 | 把客户“付不了”的原话线索归入同一张表 | 不公开客户身份信息 |
| 人工验收队列 | 把排查项分给财务、技术、运营、客服 | AI 不自动改配置或联系客户 |

## 工作机理

授权事件表 / 站点漏斗 / 脱敏 SKU 标签 / 客服反馈 → 按国家、设备、币种、支付方式聚合 → 匹配错误码和掉单位置 → 排出优先级 → 输出一页支付失败归因表 → 人类主管确认配置、话术和风险。

## 真实任务提示词

### 支付失败早报

```text
请分析这份已脱敏的支付失败事件表。字段包括：date, country, currency, payment_method, decline_code, checkout_step, sku_tag, order_value_range。请输出：昨天失败最多的 5 个组合、可能原因、需要谁确认、今天优先排查动作。不要推断客户身份，不要建议自动扣款。
```

### 漏斗异常归因

```text
下面是独立站最近 7 天的漏斗数据：product_view, add_to_cart, begin_checkout, payment_failed, purchase，按国家和设备拆分。请找出支付失败率异常升高的国家/设备组合，给出 3 个最可能原因，并写成老板能看懂的一页清单。
```

### 客服反馈匹配

```text
请阅读这些已脱敏客服反馈，只提取与支付失败相关的原话线索，例如“付不了”“银行拒绝”“验证码收不到”“没有本地支付方式”。请按问题类型归类，并和支付失败错误码表合并，输出需要客服、财务、技术分别确认的事项。
```

## 人类主管验收

- 失败率是否按国家、支付方式、设备拆开看，而不是只看总数。
- 是否出现同一种错误码突然集中。
- 高客单价 SKU 是否受到影响。
- 是否有明确负责人：运营查页面、财务查收款、技术查事件、客服查反馈。
- AI 是否没有读取个人敏感信息、没有保存密钥、没有自动改配置。

## 第一周试点

| 日期 | 动作 | 验收 |
|---|---|---|
| Day 1 | 只接一个站点或一个店铺，导出最近 7 天脱敏支付失败事件 | 字段里无个人敏感信息 |
| Day 2 | 按国家、币种、支付方式、设备、错误码聚合 | 能看出前三个失败组合 |
| Day 3 | 接一份漏斗数据，只看 add_to_cart → checkout → payment_failed → purchase | 能定位掉单段落 |
| Day 4 | 生成第一版“支付失败归因早报” | 老板能在 3 分钟内读完 |
| Day 5 | 财务、技术、运营分别确认前三个异常 | 每个异常有负责人 |
| Day 6 | 客服补充 10 条“付不了”反馈 | 归因贴近真实客户原话 |
| Day 7 | 复盘是否找到真实漏钱点 | 至少一个修复动作进入清单 |

## 不能自动化的事

- 不能替客户解释银行拒付原因或承诺付款一定成功。
- 不能自动更改 Stripe / PayPal / Shopify Payments / WooCommerce 支付配置。
- 不能自动退款、重扣、发优惠券、改价格、联系客户或承诺赔偿。
- 不能处理银行卡号、CVV、身份证件、真实邮箱电话、支付密钥和后台 token。
- 涉及合规、拒付、欺诈、税务、合同和高金额订单必须人审。
