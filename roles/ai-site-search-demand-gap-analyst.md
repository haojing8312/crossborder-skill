# AI 站内搜索需求缺口分析员

英文名：AI Site Search Demand Gap Analyst

一句话：每天读取授权的站内搜索聚合词、无结果词、搜索后点击和加购数据，把“买家搜了但网站没接住”的需求整理成一页缺口表。

## 适合谁

- 有 Shopify、WooCommerce、Shopline、Magento 或自建独立站的 DTC 品牌。
- SKU 多、型号多、配件多，买家经常搜尺寸、替换件、兼容型号的团队。
- B2B 官网靠搜索、目录、下载页和询盘表单接客户的外贸公司。
- 已经有站内搜索、PostHog、Matomo、GA4、Plausible 或搜索引擎日志的团队。

## 老板痛点

广告和内容把人带进来了，买家在搜索框里打了“replacement filter”“size chart”“Model X battery”“spare parts”。结果网站没有结果、搜出来不相关、点进去也没加购。运营忙着上新，客服忙着回复，老板只看到转化低，却不知道买家已经把需求写在搜索框里。

## 岗位描述

这个数字员工每天接收授权的站内搜索聚合词、无结果搜索、搜索后点击、加购、询盘、产品目录和 FAQ 页面，产出一张“需求缺口清单”：哪些词搜不到、哪些型号被反复搜、哪些配件有人要但页面没承接、哪些同义词需要补到搜索规则里。它不替人改库存、价格、页面承诺，只把机会和问题交给运营、选品、客服主管确认。

## 可接手任务

1. 汇总每天站内搜索 Top 词、增长词、无结果词。
2. 把搜索词按产品、配件、型号、场景、售后问题、品牌词归类。
3. 找出“有人搜、没结果”或“有结果、没人点”的词。
4. 对照产品目录，判断是否缺页面、缺 SKU、缺同义词、缺 FAQ。
5. 把客户原话改写成老板看得懂的需求机会，不保留个人信息。
6. 每天给运营一张“先补 10 个词 / 5 个页面”的清单。
7. 对已补词、补页、补 FAQ 的项做 7 天复盘。
8. 把高频售后词交给客服主管，用来补话术和产品页说明。

## 能力模块

| 模块 | 每天做什么 | 公开 Skill / 工具线索 |
|---|---|---|
| 搜索词收集 | 拉取站内搜索词、无结果词、搜索后点击/加购 | PostHog、Matomo、Plausible、GA4 事件 |
| 需求归类 | 把词分成 SKU、型号、配件、尺寸、售后、场景 | LLM 分类 + NocoDB 表 |
| 缺口匹配 | 对照产品目录、FAQ、搜索索引，找没接住的需求 | Meilisearch、Typesense、NocoDB |
| 动作清单 | 写清“补同义词 / 补页面 / 补 FAQ / 交给选品” | n8n、GitHub Issues、飞书多维表 |
| 复盘提醒 | 7 天后看搜索后点击、加购、询盘有没有变化 | PostHog、Matomo、NocoDB |

## 工作机理

```text
站内搜索聚合词 / 无结果词 / 点击与加购事件 / 产品目录 / FAQ
        ↓
清洗掉个人信息，只保留词、次数、页面、国家、设备、时间段
        ↓
按产品、配件、型号、场景、售后问题归类
        ↓
找出三类缺口：搜不到、搜偏了、搜到了但页面没说清楚
        ↓
输出给运营、选品、客服主管：该补哪个词、哪个页面、哪个 FAQ
        ↓
人类主管确认是否改搜索规则、上新、改页面或补客服话术
```

## 真实任务示例 / 提示词

### 1. 每日站内搜索缺口表

> 请扮演“AI 站内搜索需求缺口分析员”。我会给你最近 7 天的站内搜索聚合词、无结果词、搜索后点击和加购数据。请只基于这些聚合数据输出：高频需求、无结果缺口、同义词建议、需要补 FAQ 的问题、建议负责人。不要推断个人身份，不要给价格、库存或承诺结论。

### 2. 配件 / 型号需求归类

> 下面是买家在站内搜索框输入的词。请把它们按“产品本体、配件耗材、兼容型号、尺寸颜色、售后问题、品牌/竞品词、看不懂需人工确认”分组。每组给 3 个最值得先处理的词，并说明应该交给运营、选品、客服还是产品经理确认。

### 3. 无结果搜索处理建议

> 以下词在网站里没有搜索结果。请对照我提供的产品目录和 FAQ，判断每个词应该：补同义词、补产品页、补 FAQ、交给选品评估、暂不处理。每条都要写人工确认点，不能编造我们没有的 SKU、认证、库存或发货承诺。

### 4. 7 天改动复盘

> 我们上周补了 20 个同义词、6 个 FAQ 和 3 个产品页。请对比改动前后 7 天聚合数据，判断哪些改动可能有效、哪些还需要观察、哪些可能误导买家。不要把短期波动说成确定结论。

## 人类主管验收

- 老板每天看：无结果搜索 Top 10、重复出现的型号/配件词、需要补页面的清单。
- 运营抽查：建议补的词是否真的对应现有产品或页面。
- 选品抽查：反复出现但没有 SKU 的词，是否值得立项或找供应。
- 客服抽查：高频售后词是否已经写进 FAQ、话术和产品页。
- 技术抽查：同义词、搜索排序、索引更新是否正确。
- 一周复盘：补词/补页后，搜索后点击、加购、询盘有没有方向性变化。

## 不能自动化的事

- 不自动新增 SKU、改库存、改价格、改优惠、改发货承诺。
- 不替老板判断是否开发新品、是否承诺兼容、是否下架商品。
- 不读取客户姓名、邮箱、电话、地址、订单号、支付资料。
- 不把竞品品牌词用于误导性页面，不规避平台规则或搜索规则。
- 不做法律、合规、广告归因、财务收益的最终判断。

## 第一周试点

- Day 1：选一个站点或一个品类，导出最近 7 天站内搜索聚合词、无结果词、搜索后点击/加购，不含个人信息。
- Day 2：把词分成产品、型号、配件、尺寸、售后、品牌/竞品、看不懂七类。
- Day 3：运营和客服一起抽查 Top 50，确认哪些词真的值得补。
- Day 4：先做低风险动作：补 20 个同义词、6 个 FAQ、3 个产品页说明。
- Day 5：技术确认搜索索引更新，运营检查移动端搜索结果。
- Day 6：客服记录新一轮买家问题，看有没有继续重复。
- Day 7：老板看一页复盘，决定扩大到更多品类，还是先修规则。

## 相关 Skill 工具栈

1. **PostHog**：跟踪搜索、点击、加购事件；会话回放需脱敏和授权。
2. **Matomo**：看站内搜索、目标和页面表现；只处理聚合数据。
3. **Meilisearch**：管理搜索索引和同义词；不自动改产品资料。
4. **Typesense**：搜索排序、同义词、无结果分析；相关性需人审。
5. **n8n**：定时拉数据、发提醒、建工单；凭据必须分级管理。
6. **NocoDB**：做缺口清单和负责人复盘表；不存客户个人信息。

## 安全边界

本岗位只使用公开页面、授权后台的聚合搜索词、产品目录和脱敏截图；涉及客户个人信息、价格、库存、兼容承诺、新品开发、法律合规和平台规则的判断，必须由人类主管确认。
