# AI 退货退款原因分析员｜AI Returns & Refund Insights Analyst

## 一句话定位

它每天把退货表、客服工单、差评、仓库备注和商品页放在一起看，找出高退款 SKU、真实退货原因和下一步整改人，帮老板少交重复亏钱的学费。

## 适合谁

- Shopify / DTC 品牌：退货理由散在 Shopify、退货应用、Gorgias/Zendesk、仓库备注里。
- Amazon / 多平台卖家：FBA/FBM 退货、退款金额、低星评论、Listing 改动需要合并判断。
- 独立站和跨境贸易公司：老板只看到退款金额上升，但不知道该改页面、查质检、查物流还是改客服 SOP。

## 老板痛点

退款最麻烦的地方，不是看到总金额，而是不知道钱为什么漏出去。客服说“客户不满意”，运营说“页面没问题”，仓库说“没发错”，供应链说“这批货正常”。最后老板只能凭感觉开会，下一周同一个 SKU 继续退。

## 岗位职责

AI 退货退款原因分析员每天接收脱敏后的退货/退款表、客服工单摘要、差评摘要、仓库/质检备注和商品页信息。它把“太小”“货不对板”“晚到”“坏了”“买错了”这类零散说法归成统一原因，按 SKU、国家、渠道、批次、物流线和页面版本排出损失清单，再给出需要人工复核和派给负责人的整改建议。

## 可接手任务

1. 统一退货原因标签。
2. 每日新增退款异常分诊。
3. 输出 SKU / 变体退货根因看板。
4. 聚类 customer note、客服备注和仓库备注。
5. 生成 Listing / 尺码图 / 包装 / FAQ 修复建议。
6. 识别物流延误、运输损坏、错发漏发等异常。
7. 输出老板周报：Top 原因、Top SKU、影响金额、owner、下周复测指标。

## 能力模块

| 模块 | 做什么 | 可对应工具 / 工作流 |
|---|---|---|
| 数据合并 | 把 Shopify / Amazon / 客服 / 仓库字段整理到一张分析表 | Airbyte、n8n、Google Sheets、DuckDB |
| 原因归类 | 把平台枚举、客户备注、客服备注翻成内部原因标签 | ChatGPT、Claude、Gemini、BERTopic |
| SKU 风险排行 | 按退款金额、退货率、国家、渠道找出最该处理的商品 | Metabase、Sheets、BI 看板 |
| 整改单生成 | 把问题交给页面、仓库、物流、质检、供应链或客服负责人 | n8n 通知、飞书/Slack、任务表 |
| 复核与评测 | 保留证据样本，标出低置信度记录，避免 AI 自作主张 | Presidio、promptfoo、Langfuse |

## 工作机理

```text
脱敏退货表 / 客服工单 / 差评 / 仓库备注 / 商品页
        ↓
原因标准化：把“太小、不合身、货不对板、晚到、坏了”归到统一标签
        ↓
交叉分析：按 SKU、国家、渠道、批次、物流线、页面版本排损失
        ↓
行动清单：改页面 / 查质检 / 查仓库 / 查物流 / 改客服 SOP
        ↓
人类主管验收：抽查样本、确认责任人、批准整改，不让 AI 自动退款
```

## 可复制提示词

### 1. 退货原因标准化映射

```text
你是跨境电商退货退款原因分析员。请把以下已脱敏退货/退款记录映射到统一原因标签。

统一标签候选：尺寸不符、颜色/款式不符、描述不符、产品缺陷、运输损坏、错发/漏发、配件缺失、物流延误、买家不想要、价格/促销、客服政策例外、疑似滥用、其他/证据不足。

输出表格字段：record_id、原始原因、客户备注摘要、标准标签、置信度高/中/低、证据句、是否需要人工复核、建议补充字段。

规则：只能基于输入数据判断；原始原因与备注冲突时标记“需人工复核”；不要输出客户姓名、邮箱、电话、地址、订单号。

数据：{{脱敏退货退款记录表}}
```

### 2. SKU / 变体根因分析

```text
请分析以下按 SKU/变体汇总的退货退款数据，找出最值得优先处理的问题。

输出：Top 10 SKU/变体风险榜；每个风险 SKU 的可能根因假设；建议动作；需要人工确认的问题和所需额外数据。

限制：不要把相关性写成确定因果；高金额或安全相关问题必须标记人工复核。

数据：{{SKU_variant_return_refund_summary}}
```

### 3. Listing 预期不符修复包

```text
下面是某 SKU 的退货原因、客户备注、低星评论摘要和当前 Listing 文案。请判断哪些退货可能由“买家预期不符”导致，并给出页面修复建议。

输出表格：问题类型、证据、当前 Listing 缺口、建议修改位置、建议文案草稿、需人工确认项。

规则：不新增未经证实的产品功效、认证、保修或交付承诺；需要产品、法务、合规或供应链确认时明确标注；不建议诱导客户改评价或撤销退货。

输入：{{return_reason_notes}} / {{review_summary}} / {{listing_copy}} / {{public_product_specs}}
```

## 第一周试点

- **Day 0：选范围**。选 1 个渠道、1 条产品线、最近 30–90 天数据；确定只读权限、脱敏规则、不可自动退款边界、复核人。
- **Day 1：统一字段**。导出退货/退款表、客服工单摘要、仓库质检备注、Listing 改动记录；移除或哈希订单号、邮箱、姓名、电话、地址。
- **Day 2：建立原因标签**。抽样 100–300 条记录，建立 10–15 个标准原因标签；AI 初判并抽样人工复核。
- **Day 3：找 Top 问题**。按 SKU/变体/市场/渠道/物流方式生成 Pareto，识别 Top 5 金额原因和 Top 5 异常 SKU。
- **Day 4：派整改 owner**。把问题转成页面、尺码图、包装、说明书、质检、仓库、物流、客服 SOP 的整改项。
- **Day 5：老板验收**。提交 1 页老板摘要、1 张明细表和下周复测指标。

## 人类主管验收

老板 / 运营负责人每天只看 5 件事：

1. Top 退款原因是否有证据样本，不只看平台枚举。
2. 高退款 SKU 是否标出金额区间、退货率、渠道、国家和时间变化。
3. 每条建议是否能派给具体负责人。
4. P0/P1 样本是否人工抽查；AI 置信度低的记录是否进入复核队列。
5. 整改后下周是否复测：退款金额、退货率、客服工单量、换货率、同类原因占比。

## 不能自动化的事

- 不自动批准、拒绝或发起退款、换货、赔偿、拒付争议处理、价格例外或客户补偿。
- 不自动联系客户，不自动发送承诺性售后话术，不诱导客户修改/删除评论或撤销投诉。
- 不把 AI 分类结果当作最终财务、质量、法律或平台合规结论。
- 不使用未脱敏客户个人信息、支付信息、地址、订单详情做外部模型分析或公开示例。
- 不把供应商合同、采购价、毛利、内部质检报告、未公开产品资料、平台账号 token 放进提示词或公共仓库。
- 不绕过 Shopify/Amazon/Zendesk/Gorgias/退货应用的权限、API 限制、验证码或平台条款做抓取。
