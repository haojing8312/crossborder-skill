# AI 库存补货预警员

> 每天替老板盯库存、算补货、提前报缺货风险。  
> 英文岗位名：AI Inventory Replenishment Alert Analyst

## 这个岗位适合谁

- Amazon / Shopify / TikTok Shop 有 20 个以上常备 SKU 的跨境团队。
- 经常遇到爆款断货、慢货压仓、采购排期混乱的老板。
- 运营、采购、仓库各看一张表，开会总说不清先补谁的团队。
- 有 FBA、海外仓、在途货柜、供应商交期数据，但没人每天合起来看的公司。

## 老板会立刻听懂的痛点

老板真正怕的是两件事：爆款断货，慢货压仓。

爆款断货时，广告还在烧，排名掉下去，客户转头买竞品。慢货压仓时，现金被库存占着，海外仓租金每天在算，采购还可能按老经验继续下单。

很多团队不是没有数据，而是数据散在平台后台、ERP、库存表、采购表、聊天记录里。老板每周都要追问：这一款还能卖几天？下一批什么时候到？这个 SKU 到底该不该补？

## 数字员工每天接什么输入

- SKU 编码和产品简称
- 当前可售库存
- FBA / 海外仓库存
- 在途数量
- 近 7 / 14 / 30 天销量
- 采购交期
- 入仓周期
- 目标覆盖天数
- 安全库存天数
- 活动、广告、季节品标记

## 每天交付什么结果

1. 高风险缺货 SKU 清单。
2. 预计断货日期。
3. 建议补货量草案。
4. 最晚下单日。
5. 滞销和积压 SKU 清单。
6. 数据异常清单。
7. 老板版 1 页库存日报。
8. 采购需要确认的优先级列表。

## 可接手任务

- 每天生成缺货风险清单。
- 计算每个 SKU 的库存可售天数。
- 标出预计 7 / 14 / 21 天内断货的 SKU。
- 识别滞销、积压、高库存低销量 SKU。
- 生成补货数量草案和最晚下单日。
- 发现库存为负、SKU 重复、交期缺失、在途长期不更新等数据问题。
- 写老板版库存日报和周报。
- 把采购需要确认的 SKU 排优先级。

## 能力模块

| 模块 | 做什么 | 老板看到的结果 |
|---|---|---|
| 库存雷达 | 看可售库存、FBA 在途、海外仓余量、SKU 状态 | 今天哪些货快不够了 |
| 销量消耗计算 | 按近 7/14/30 天销量算日均销量和可售天数 | 这款还能卖几天 |
| 补货建议草案 | 结合交期、入仓周期、安全库存给建议量 | 采购先补哪几款 |
| 异常解释 | 说明风险来自广告放量、物流延迟、采购未下单还是数据缺失 | 开会不用翻聊天记录 |
| 老板日报 | 输出“今天必须处理的 5 个 SKU” | 老板只看红色风险 |

## 工作机理

```text
库存日报 + 订单销量 + 在途货柜 + 供应商交期 + 促销日历
→ 算日均销量
→ 算库存可售天数
→ 加入在途和安全库存
→ 判断缺货日期
→ 按红黄绿分级
→ 输出建议动作和人工确认点
```

## 真实任务提示词

### 1. 每日缺货风险分析

```text
你是跨境电商库存补货预警助理。请根据以下脱敏 SKU 库存数据，计算每个 SKU 的库存可售天数、预计断货日期和风险等级。

规则：
1. 日均销量 = 近 30 天销量 / 30。
2. 库存可售天数 = 当前可售库存 / 日均销量。
3. 若日均销量为 0，请标记为“无近期销量，需人工判断”。
4. 红色风险：库存可售天数 < 采购交期 + 入仓周期。
5. 橙色风险：库存可售天数 < 采购交期 + 入仓周期 + 7。
6. 黄色风险：库存可售天数 < 目标覆盖天数。
7. 只输出建议，不要生成采购单，不要假设供应商信息。

请输出表格：SKU｜当前库存｜近30天销量｜日均销量｜库存可售天数｜预计断货日期｜风险等级｜建议动作｜需要人工复核的问题

数据如下：
[粘贴脱敏数据]
```

### 2. 补货数量建议草案

```text
你是 AI Inventory Replenishment Alert Analyst。请基于以下脱敏库存数据生成补货建议草案。

计算逻辑：
1. 交期内需求 = 日均销量 ×（采购交期 + 入仓周期）。
2. 安全库存 = 日均销量 × 安全库存天数。
3. 目标库存 = 日均销量 × 目标覆盖天数。
4. 建议补货量 = 目标库存 - 当前可售库存 - 在途库存。
5. 如果建议补货量小于 0，请标记为“暂不建议补货”。
6. 输出保守、标准、激进三档建议：保守覆盖 30 天，标准覆盖 45 天，激进覆盖 60 天。
7. 不要使用客户隐私、报价、合同或供应商信息。
8. 最终采购数量必须标记为“需人工确认”。

请输出：SKU｜日均销量｜当前库存｜在途库存｜交期｜安全库存｜保守补货｜标准补货｜激进补货｜建议优先级｜人工确认点

数据如下：
[粘贴脱敏数据]
```

### 3. 滞销与库存积压识别

```text
你是跨境电商库存周转分析助理。请识别以下 SKU 中的滞销、积压和暂停采购风险。

判断规则：
1. 近 30 天销量为 0 且当前库存 > 0：严重滞销。
2. 库存可售天数 > 180 天：高积压风险。
3. 库存可售天数在 90–180 天：中度积压风险。
4. 近 30 天销量下降超过 50%，且库存较高：需关注。
5. 新品、季节品、活动品请单独标记，避免误判。
6. 不要给出降价幅度，不要使用真实成本或报价。
7. 只输出运营建议草案。

请输出：SKU｜当前库存｜近30天销量｜近60天销量｜库存可售天数｜风险类型｜建议动作｜是否需人工复核

数据如下：
[粘贴脱敏库存表]
```

## 人类主管验收

老板、运营和采购每天看：

- 红色风险 SKU 是否真实需要处理。
- 预计断货日期是否合理。
- 建议补货量是否过高或过低。
- 在途库存和供应商交期是否准确。
- 活动、广告、季节性是否被正确标记。
- AI 是否误把新品、停产款、清仓款当成正常 SKU。

## 不能自动化的事

- 最终采购、供应商选择、下单时间、运输方式。
- 报价、合同、账期、付款条款和真实成本判断。
- 自动修改库存、价格、商品上下架。
- 使用客户姓名、电话、邮箱、地址、大客户订单。
- 实物盘点、破损检查、批次核验、海外仓入库确认。

## 第一周试点

1. 选 20–50 个主推 SKU，统一 SKU 名称。
2. 导出近 30 天销量、当前库存、在途数量、采购交期。
3. 设置红黄绿预警规则。
4. 生成第一版补货预警表。
5. 让采购确认“该补、别补、先查”的 SKU。
6. 复盘误报，调整安全库存和活动品规则。
7. 验收：是否提前发现断货点，是否减少人工查表，采购是否知道先补谁。

## 安全边界

本岗位只做预警和建议草案，不接管采购决策；只读数据，不改库存、价格和订单；不输入客户隐私、报价、合同和未公开产品信息。
