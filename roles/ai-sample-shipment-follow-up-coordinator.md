# AI 样品寄送跟单员

> 样品寄出去以后，每天替老板盯住物流、签收、反馈和下一步动作，避免样品线索靠销售记性慢慢漏掉。

## 适合谁

- B2B 外贸工厂、OEM/ODM、贸易公司。
- 经常寄样、打样、参加展会后批量寄样的团队。
- 销售跟进靠个人记性，老板看不清样品转化进度的团队。
- 已有样品表格、运单号、邮箱/WhatsApp 跟进记录的团队。

## 老板痛点

很多订单机会在报价前就开始漏。样品寄出去之后，DHL 显示已签收三天了，客户有没有测试？销售有没有问反馈？客户说“下周看”，下周到底谁再追一次？这些小事没人盯，样品费、运费、打样时间就慢慢漏掉了。

## 这个数字员工每天做什么

输入：脱敏样品台账、运单号、物流状态、销售负责人、邮件摘要和客户反馈片段。  
处理：按样品 ID 对齐客户、SKU、国家、寄出日期和负责人；再把物流和邮件状态分组。  
输出：今日样品跟进板、销售待办、跟进草稿、老板漏斗、异常样品清单。

它不谈价格、不承诺交期，只把“今天该谁跟、跟什么、凭什么判断”写清楚。

## 可接手任务

1. 汇总新增样品、待寄样、已寄样、签收、异常和已反馈状态。
2. 按运单号整理物流状态：未揽收、运输中、清关异常、已签收、退回。
3. 标记“已签收 2–3 天但销售没跟进”的样品。
4. 把邮件摘要里的“收到、测试中、需要资料、下周反馈、暂缓”归类。
5. 写确认签收、询问测试反馈、补发资料的跟进草稿。
6. 把反馈分成产品问题、包装问题、资料缺口、价格待谈、采购时点。
7. 给老板输出样品漏斗：寄出、签收、反馈、异常、主管介入。
8. 标记高价值客户、物流异常、质量反馈等需要主管看的样品。

## 能力模块

| 模块 | 具体动作 | 工具线索 |
|---|---|---|
| 样品台账整理 | 对齐样品 ID、SKU、国家、运单号、销售负责人 | NocoDB、表格 |
| 物流状态跟踪 | 查运单状态，标记签收和异常 | AfterShip Tracking SDK、承运商公开查询/授权 API |
| 邮件摘要归类 | 只抽取业务阶段和下一步，不处理隐私细节 | Gmail API、LLM 结构化输出 |
| 跟进草稿生成 | 写邮件/WhatsApp 草稿，由销售确认发送 | ChatGPT / Claude / Gemini |
| 老板看板提醒 | 每天输出样品漏斗和异常样品 | n8n、Huginn、飞书/Slack/NocoDB |

## 工作机理

样品台账 + 运单号 + 邮件摘要 → 统一样品 ID → 物流状态分组 → 邮件阶段归类 → 生成销售待办和跟进草稿 → 人工确认发送 → 老板看样品漏斗和异常清单。

## 可复制提示词

```text
你是外贸公司的样品寄送跟单员。请只基于我提供的脱敏样品台账和物流状态整理，不要编造客户信息。输出：样品ID、当前阶段、今天是否需要动作、建议动作、负责人、证据、是否需要主管确认。阶段只能使用：待寄样/在途/物流异常/已签收未跟进/已跟进待反馈/客户已反馈/暂停。
```

```text
请把下面的脱敏邮件摘要归类成样品跟进阶段。不要生成正式承诺，不要推测客户预算。输出：客户反馈类型、下一步动作、建议销售在几天内跟进、是否需要技术/老板介入、不能自动发送的原因。
```

```text
请为“样品已签收 2 天但客户未反馈”的客户写 2 版跟进草稿：一版英文邮件，一版 WhatsApp 短消息。语气礼貌、短，不承诺价格和交期，只确认是否收到、是否需要测试资料、是否方便约 15 分钟反馈。最后提醒：发送前销售必须人工确认客户姓名、产品名和附件。
```

```text
请根据这 30 个样品记录生成老板看板。老板只看 6 个数字：本周寄出、已签收、签收未跟进、已收到反馈、需要主管介入、物流异常。每个异常样品列出证据和负责人，不要包含客户电话、地址、报价或合同信息。
```

## 第一周试点

- Day 1：选最近 30–50 个样品，整理脱敏台账：样品 ID、SKU、国家、寄出日期、运单号、销售负责人、当前阶段。
- Day 2：接入一个物流状态来源或人工导入物流结果，先不接邮箱发送权限。
- Day 3：把样品分成待寄、在途、异常、已签收未跟进、已反馈。
- Day 4：生成 3 种跟进草稿：确认签收、询问测试反馈、补发资料；销售只发确认后的版本。
- Day 5：老板抽查 10 个样品，看状态是否准确、提醒是否合适、是否有隐私越界。
- Day 6：补一个“高价值客户 / 异常样品”人工升级规则。
- Day 7：复盘签收未跟进数、反馈回收数、误报数、主管介入数。

## 人类主管验收

老板每天看 6 个数：本周寄出、已签收、签收未跟进、已收到反馈、需要主管介入、物流异常。销售主管抽查样品状态是否真实，跟进草稿是否越界，是否遗漏高价值客户。涉及价格、交期、样品费、合同和客户承诺的内容必须人审。

## 不能自动化的事

- 不自动承诺交期、样品费、运费承担、折扣、付款方式、独家代理、MOQ 或合同条款。
- 不自动发送正式报价、合同、PI、发票或法律文件。
- 不擅自修改客户地址、收件人、清关资料和物流账号信息。
- 不上传客户电话、私人地址、护照、付款信息、合同、报价单、利润等敏感资料到不受控模型。
- 不把物流异常解释成公司责任；只提示“需要人确认”。

## 相关 Skill / repo / 工作流

1. n8n — https://github.com/n8n-io/n8n：串联表格、邮箱、HTTP API 和提醒；风险是密钥和权限必须最小化。
2. Huginn — https://github.com/huginn/huginn：监听事件和变化；风险是不绕过登录、验证码和平台限制。
3. AfterShip Tracking SDK — https://github.com/AfterShip/tracking-sdk-python：物流轨迹接入；风险是 API 账号、收件信息和密钥必须保护。
4. Gmail API — https://developers.google.com/workspace/gmail/api/guides：在授权范围内读取摘要和生成草稿；风险是不自动发送正式承诺。
5. NocoDB — https://github.com/nocodb/nocodb：样品跟进看板；风险是权限分层，避免公开客户资料。

## 风险分级

- 内容安全：PASS，使用公开资料和脱敏试点设定。
- 隐私：不得上传客户姓名、电话、地址、报价、合同、付款和内部利润数据。
- 发布：外部正式发布仍需郝敬确认。
