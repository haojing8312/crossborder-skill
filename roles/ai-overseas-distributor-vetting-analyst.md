# AI 海外经销商背景核验员

> 客户说“我有渠道”，它先替老板查一遍公开证据，再把值得聊、要补资料、先暂缓的经销商线索分出来。

## 适合谁

- B2B 外贸工厂、工业品、消费品品牌出海团队。
- 正在招海外代理、经销商、进口商、批发商的老板。
- 销售经常收到 “We are distributor / importer” 询盘，但没时间先查背景的团队。
- 已有询盘表、公司名、官网、邮箱域名、国家和产品线字段的团队。

## 老板痛点

海外客户说自己有渠道、有仓库、有门店，邮件写得也热情。可老板真正想知道的是：这个公司公开资料查得到吗？官网和邮箱域名对得上吗？它平时卖的品类和我们匹配吗？有没有展会、行业目录、门店或公开评价的痕迹？

没人先查，销售就容易陪一个不合适的代理聊半个月；真有渠道的人，也可能被混在一堆普通询盘里。

## 这个数字员工每天做什么

输入：经销商询盘、公司名、国家、官网、邮箱域名、联系人职位、目标产品线、公开网页和授权 CRM 摘要。  
处理：查公开资料，核对公司名、域名、地址、品类和联系人信息，找冲突，列补问问题。  
输出：经销商背景卡、A/B/C 跟进队列、证据链接、风险点、英文补问邮件草稿、老板抽查清单。

它不替老板授权代理，也不下法律结论。它只把“凭什么值得继续聊”写清楚。

## 可接手任务

1. 整理新经销商询盘：公司名、国家、官网、邮箱域名、产品线、来源。
2. 查询公开公司资料、官网、行业目录、展会名录、新闻页、地图/门店页。
3. 检查公司名、域名、国家、地址、主营品类和联系人职位是否冲突。
4. 按证据把线索分成 A/B/C：优先聊、补资料、暂缓。
5. 生成销售下一步问题：渠道覆盖、现有品牌、客户类型、仓储/售后能力、预计首批采购。
6. 标记风险：官网不可用、邮箱域名不一致、品类不匹配、公开资料太少、疑似中间商。
7. 输出老板日报：今日新增、A 类、需补资料、暂缓、资料冲突、需主管抽查。
8. 写礼貌英文补问邮件草稿，由销售确认后再发。

## 能力模块

| 模块 | 具体动作 | 工具线索 |
|---|---|---|
| 公开资料查找 | 找官网、注册页、行业目录、展会页 | Google Custom Search、Firecrawl、Crawlee、OpenCorporates |
| 一致性核验 | 对公司名、域名、地址、品类做交叉检查 | NocoDB、表格、LLM 结构化抽取 |
| 渠道匹配评分 | 判断像进口商、批发商、零售商还是普通询盘 | 自定义评分表、CRM 字段 |
| 风险问题生成 | 只写需要人工确认的问题 | ChatGPT / Claude / Gemini |
| 跟进看板 | 推送 A/B/C 队列和主管抽查样本 | n8n、Activepieces、飞书/Slack |

## 工作机理

经销商询盘 + 公司名 + 官网/邮箱域名 + 国家/品类 → 公开资料查找 → 一致性检查 → 品类/渠道匹配 → 风险点和补问清单 → A/B/C 跟进队列 → 销售主管抽查 → 人工决定是否继续商务沟通。

## 第一周试点

- Day 1：选最近 20–50 条海外经销商询盘，整理公司名、国家、官网、邮箱域名、产品线、来源；去掉私人电话和报价信息。
- Day 2：定义评分表：公开痕迹、品类匹配、渠道能力、资料一致性、风险项，各 0–5 分。
- Day 3：跑第一轮公开资料查找，生成经销商背景卡和证据链接。
- Day 4：销售主管抽查 10 条，修正误判和评分口径。
- Day 5：生成 A/B/C 跟进队列和英文补问邮件草稿。
- Day 6：销售只给人工确认过的 A/B 类线索发邮件。
- Day 7：复盘 A 类回复率、补资料完成数、误报数、被主管打回的原因。

## 人类主管验收

老板每天看 6 个数：今日新增、A 类优先跟进、需补资料、暂缓、资料冲突、需主管抽查。销售主管抽查背景卡里的证据是否真实，补问问题是否具体，风险标记有没有误伤正常小公司。代理权、价格、账期、合同、返点和区域保护必须人审。

## 不能自动化的事

- 不自动承诺独家代理、区域保护、价格、返点、账期、MOQ、样品费、售后责任或合同条款。
- 不发送正式授权书、报价单、合同、PI、发票或法律文件。
- 不抓取登录后页面、私人社交信息、私人电话、银行资料、身份证件或客户内部文件。
- 不把公开资料少直接写成骗子；只能写需要人工补充核验。
- 不替代法务、财务风控、信用保险或本地律师尽调。

## 相关 Skill / repo / 工作流

1. n8n — https://github.com/n8n-io/n8n：串联询盘表、搜索 API、看板和提醒；风险是密钥最小权限，不把客户敏感信息进提示词。
2. Firecrawl — https://github.com/firecrawl/firecrawl：把公开网页转成可读文本；风险是不绕过登录、验证码和网站限制。
3. Crawlee — https://github.com/apify/crawlee：采集公开目录/官网页面；风险是遵守 robots、频率和目标站点条款。
4. NocoDB — https://github.com/nocodb/nocodb：做经销商候选看板和人工复核字段；风险是权限分层，避免公开客户资料。
5. OpenCorporates API — https://api.opencorporates.com/documentation/API-Reference：公司公开注册信息线索；风险是覆盖国家有限，不能替代正式尽调。

## 风险分级

- 内容安全：PASS，使用公开资料和脱敏试点设定。
- 隐私：不得上传客户私人电话、个人地址、银行资料、报价、合同、付款、利润和内部渠道政策。
- 商务/法务：不得自动授权代理、承诺价格或给出法律结论。
- 发布：外部正式发布仍需郝敬确认。
