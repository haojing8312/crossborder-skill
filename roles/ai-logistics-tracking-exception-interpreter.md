# AI 物流轨迹异常解释员

> 每天认识一个出海 AI 员工：它不替老板承诺赔付，只先把异常包裹的事实、责任方和客服回复摆清楚。

## 适合谁
- DTC / 独立站老板：客服每天被“包裹为什么不动”拖住。
- 亚马逊、TikTok Shop、eBay、Walmart 卖家：物流异常会影响差评、退款和平台绩效。
- 有海外仓、3PL 或外贸样品寄送的团队：仓库、货代、承运商、客服信息经常断开。

## 老板痛点
客户问进度时，客服常常只复制承运商页面上的英文状态。老板真正要的不是 tracking 链接，而是三件事：包裹卡在哪，大概率谁能处理，今天该怎么回复客户。

## 这个岗位每天做什么
输入：订单号、物流单号、承运商、发货日期、最新轨迹文本、客户留言、客服工单。

输出：
- 今日物流异常解释表；
- 每个异常单号的中文解释；
- 下一步责任方：客服 / 仓库 / 货代 / 承运商 / 主管；
- 可复制客服回复草稿；
- 需要老板或客服主管确认的高风险清单。

## 可接手任务
1. 找出 48/72 小时没有更新的单号。
2. 标记标签已建未揽收、清关延迟、派送失败、地址异常、疑似退回、疑似丢件。
3. 把英文 tracking 状态改写成客服和老板都看得懂的中文解释。
4. 给每个异常单号指定下一步处理人。
5. 生成不能乱承诺时效和赔付的客服回复草稿。
6. 每天汇总新增异常、超过 3 天未解决、可能导致差评/退款的订单。
7. 每周归因：哪个国家、渠道、SKU、仓库或地址质量最容易出问题。

## 能力模块
| 模块 | 具体做法 | 可参考工具 |
|---|---|---|
| 轨迹抓取与汇总 | 定时拉取订单、单号、承运商状态 | n8n / Prefect |
| 异常分类 | 未揽收、无更新、清关、派送失败、地址、退回、疑似丢件 | LLM + 表格规则 |
| 回复生成 | 写自然客服话术，保留人工确认边界 | ChatGPT / Claude / Gemini |
| 告警与日志 | 记录任务失败、API 报错、异常频率 | Sentry / SigNoz / OpenObserve |
| 证据归档 | 保存 tracking 截图、索赔材料、客服沟通记录 | Paperless-ngx |

## 工作机理
订单 / 单号 / 客户留言 → 拉取承运商轨迹 → 判断异常类型 → 解释可能原因 → 给出下一步动作 → 生成人类可审核回复 → 客服主管确认高风险单 → 每日给老板看 3 个数字。

## 可复制任务提示词

### 1. 单个异常解释
请扮演跨境物流轨迹异常解释员。根据订单日期、发货日期、承运商、目的国、最新 tracking 文本和客户留言，输出：这个状态大概率发生了什么；异常类型；今天该找客服、仓库、货代还是承运商；一版不能承诺具体送达日期和赔付的客服回复。

### 2. 批量分拣异常订单
下面是一批订单物流状态。请按客户风险从高到低排序，输出：订单号、异常类型、客户风险、责任方、今天动作、是否需要主管确认。超过 72 小时无更新、派送失败、客户二次催问优先级更高；涉及退款、补发、赔付必须主管确认。

### 3. 客服回复改写
请把下面这段物流异常说明改写成 3 版客服回复：简短安抚版、需要客户补地址版、等待承运商确认版。不要说“保证明天送达”，不要主动承诺退款或补发，要说明我们正在查什么、下一次什么时候更新。

## 人类主管验收
- 每天看：新增异常数、超过 3 天未解决数、可能差评/退款数。
- 每天抽查：10–20 个 AI 解释是否有事实依据，客服回复有没有乱承诺。
- 每周看：异常最多的目的国、渠道、SKU、仓库，决定是否换线路或改客服 SOP。

## 不能自动化的事
- 不能自动承诺送达日期、赔付、退款、补发。
- 不能替代承运商官方结论、保险索赔、平台申诉或法律判断。
- 不能把客户地址、电话、邮箱等隐私信息发给未经授权的外部工具。
- 高金额、高投诉风险订单必须人工确认。

## 第一周试点
1. 选最近 50 个客户催问物流的订单，整理单号、承运商、发货日、最新状态、客户留言。
2. 建异常分类表，让 AI 逐条解释并给下一步动作。
3. 客服主管抽查 20 单，改掉事实不准、语气太满、承诺越界的句子。
4. 用 n8n 或 Prefect 做每天定时汇总，推到表格或飞书群。
5. 老板只看 3 个数：新增异常、3 天未解、可能引发差评/退款。

## 相关 Skill 工具栈
- [n8n](https://github.com/n8n-io/n8n)：连接承运商 API、Shopify/ERP、表格和飞书通知。风险：凭据和客户隐私要隔离。
- [Prefect](https://github.com/PrefectHQ/prefect)：定时运行物流异常检查流程，适合有技术维护能力的团队。
- [Sentry](https://github.com/getsentry/sentry)：监控流程报错、通知失败、API 异常，避免系统悄悄停掉。
- [SigNoz](https://github.com/SigNoz/signoz)：看异常频率和日志趋势，适合订单量更大的团队。
- [Paperless-ngx](https://github.com/paperless-ngx/paperless-ngx)：归档物流截图、索赔材料和沟通记录。风险：权限与脱敏要做好。

## 安全边界
可公开讲岗位和流程；不可公开客户真实订单、地址、电话、邮箱、承运商合同价、赔付策略或平台申诉细节。该岗位只做解释、分诊和提醒，不替代客服主管、承运商或法务/合规判断。
